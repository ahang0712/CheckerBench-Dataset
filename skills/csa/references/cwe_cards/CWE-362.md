# CWE-362: Concurrent Execution (Race Condition)
> Tier: 2 | Global samples: 64 | ⚠️ 89%+ kernel-class — userspace applicability unverified

## 1. Typical Code Patterns

A race condition arises when the correctness of an operation depends on the
interleaving of concurrent execution flows (threads, processes, signals, or
interrupts). In C/C++ the following patterns dominate:

- **TOCTOU (Time-of-Check / Time-of-Use)** — a resource is probed for a
  property (exists, writable, length), then used under the assumption the
  property still holds; the window between check and use is unsynchronized.
  *Example:* `access("/tmp/lock", F_OK)` followed by `open("/tmp/lock", O_CREAT)`.

- **Unlocked shared state** — a global or heap-allocated variable (flag,
  counter, list head) is read by one thread and written by another without a
  mutex, atomic, or memory barrier protecting the access. *Example:* a
  `static int refcount` incremented/decremented without atomics.

- **Double-fetch from shared memory** — kernel code copies data from
  userspace, validates it, then copies the *same field* again; the second
  fetch may see a different value (userspace mutates the buffer between the
  two copies).

- **Signal-handler reentrancy** — a non-atomic update (e.g., `free()`) inside
  `SIGCHLD` / `SIGINT` handler collides with the same operation in the main
  thread.

- **Check-then-commit with insufficient locking** — a driver ioctl validates
  device state, then performs an action, but the kernel preempts the thread
  between the two steps, allowing another execution context to invalidate the
  pre-condition.

## 2. CSA Checker Architecture Recommendations

- **Base class:** `Checker<check::PreCall, check::EndAnalysis>` or
  `Checker<check::Location>`. For TOCTOU, a
  `check::EndFunction` callback is often needed to pair check/use sites.

- **Callbacks:**
  - `check::PreCall` — intercept syscalls or library functions that act as
    check points (`access`, `stat`, `fopen`, `copy_from_user`).
  - `check::Location` — monitor reads/writes to tracked memory regions.
  - `check::EndFunction` — flush unresolved check → use pairs as warnings.

- **Tracking granularity:** Symbolic region + access type (read/write) +
  thread-ID context (when available). A **pending check set** (map from
  checked property → checked region) is the core data structure. When a
  matching *use* is reached without intervening synchronization, emit a
  warning.

- **Cross-reference:** See `csa_checker_patterns.md` §§ “Cross-Call State
  Machine” and “Tagged Access Pairs”.  For double-fetch, model two
  `MemRegion` loads at different source locations and compare.

## 3. Known High-Frequency False Positive Patterns

- **Single-threaded code paths analyzed as multi-threaded** — CSA may assume
  any global is concurrently accessible.  Constrain warnings to symbols
  annotated `_Atomic`, `__thread`, or explicitly shared (e.g., kernel
  `struct task_struct` members).

- **Accesses protected by a mutex the analyzer cannot model** — e.g.,
  bitfield-guided locking, lock-free sequences, or lock-tracking that
  requires interprocedural alias analysis.  Suppress by recognizing known
  lock/unlock idioms (spin_lock / spin_unlock via `check::PreCall`).

- **TOCTOU that is actually safe** — the “use” reconstructs the resource
  handle from scratch so the race window is empty (e.g.,
  `realpath()` + `open()` in glibc).  Distinguish by checking whether the
  argument to the use-site is *derived from* the check-site value (dataflow).

- **Kernel copy_from_user double-fetch patterns that are intentional** —
  some drivers deliberately re-fetch metadata after a sanity check; annotate
  or whitelist.

## 4. Generic Discriminant Features

| Dimension | Textbook (likely real) | Variant (likely FP / low severity) |
|-----------|------------------------|-------------------------------------|
| Access pair distance | Crossing function / syscall boundary | Within same basic block or lock/unlock pair |
| Synchronization | Zero sync between check and use | Mutex held, atomic ops, or memory barrier present |
| Protection pattern | Unlocked + multiple writers | Single writer / single reader (safe) |
| TOCTOU resource | File system path, device memory | Stack-local or heap memory reachable only from one thread |
| Double-fetch alignment | Same field, different generated loads | Loads hoisted by optimizer (identical value) |
| Signal-safety | Non-reentrant function (malloc, printf) inside handler | Reentrant function (write, sig_atomic_t) |
