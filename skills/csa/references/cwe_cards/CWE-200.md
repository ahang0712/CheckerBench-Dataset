# CWE-200: Exposure of Sensitive Information
> Tier: 2 | Global samples: 21

## 1. Typical Code Patterns

**Memory disclosure (most common in C/C++):**
- **Uninitialized memory leak:** Stack/struct fields left uninitialized before `write()`, `send()`, `memcpy()` to untrusted output — bytes adjacent to initialized data escape.
- **Partial struct initialization:** `struct { int a; char buf[64]; } s = { .a = 42 };` — padding bytes and `buf` remain indeterminate; copying the whole struct leaks stack contents.
- **Insufficient null-termination:** `strncpy(dst, src, n)` without explicit `dst[n-1] = '\0'`; concatenation or print of `dst` walks past intended boundary.
- **Heartbleed-style over-read:** `memcpy(out, in, user_len)` where `user_len > actual_len`; attacker-controlled length exfiltrates adjacent heap.

**Side channels:**
- **Key-dependent control flow:** `if (secret_byte) goto slow_path` — timing varies with secret.
- **Cache-timing via table lookup:** AES T-table or similar with secret-indexed loads.
- **Branch-on-secret asm constraint:** `if (password[i] != input[i]) return -1;` — early exit leaks comparison position.

**Error / debug disclosure:**
- Printing secrets to `stderr` / syslog / debug buffers that escape to user.
- Including full stack traces, environment variables, or file paths in error responses.

## 2. CSA Checker Architecture Recommendations

**Base class:** `BuiltinBugCheck` or custom `Checker<check::EndFunction>` for uninit tracking; `check::PreCall` / `check::PostCall` for taint propagation.

**Callbacks:**
- `checkEndFunction` → scan for struct variables where only a subset of fields are assigned before escaping via `memcpy` / `send` / `write`.
- `checkPreCall` / `checkPostCall` → annotate sensitive sinks (`send`, `write`, `printf`) and sources (`getenv`, `read_password`, `RAND_bytes`).
- For side channels: `checkBranchCondition` + `checkLocation` to detect secret-dependent control flow.

**Tracking granularity:**
- **Symbolic region + bitwise offset/length** for partial initialization checks.
- **Taint tags** for secret propagation: tag data at source, allow-list trusted sinks (e.g., `memcmp`), warn on untrusted sinks.
- Cross-reference `csa_checker_patterns.md` for region-store traversal and `SVal` / `DefinedOrUnknown` helpers.

**State merged at:** Call edges (accumulate taint from callee returns); loop back-edges (conservatively widen).

## 3. Known High-Frequency False Positive Patterns

1. **Padding bytes in packed structs:** `__attribute__((packed))` structs used for wire protocols — padding is intentional zero-fill; CSA warns on all uninitialized bytes. Mitigation: suppress when struct is trivially-copyable and whole-memcpy'd immediately after zero-init.

2. **Cryptographic comparisons (side channel):** `CRYPTO_memcmp`, `timingsafe_memcmp` — constant-time functions still contain conditional branches internally. CSA flags them unless the checker recognizes the function as a safe comparison sink.

3. **Audit logging:** Storing secrets in a `syslog` buffer that is explicitly internal — false positive if `syslog` is an allowed sink. Mitigation: configurable sink allow-list.

4. **`memset`-then-`free` patterns:** Clearing a secret before freeing memory — checker sees a write to sensitive memory but warns about the read in `memset(param, 0, len)`. Track that `memset` of a secret-tagged region clears the taint.

5. **Padding in untagged unions:** `union { char c; int x; }` — writing `c` only then copying the whole union; padding bits are compiler-defined. Suppress on union types smaller than word size.

## 4. Generic Discriminant Features

| Dimension | Textbook (high confidence) | Variant / borderline |
|---|---|---|
| **Scope of leak** | Uninitialized bytes from local stack frame reach a network sink via `send()` / `write()` | Padding bytes in protocol structs; compiler-inserted alignment holes |
| **Sink type** | Cross-privilege boundary (socket, pipe to child, shared memory to unpriv process) | Same-privilege internal log; debug `printf` |
| **Source of sensitivity** | Explicit taint source (`read_password`, `EVP_PKEY_new`) | Implicit — any uninitialized read from a struct with some initialized fields |
| **Side-channel signal** | Secret-indexed memory load inside a loop (cache timing) | Single branch on a public nonce; infrequent or amortized timing |
| **Attacker proximity** | Remote attacker can trigger exploit repeatedly | Local attacker with existing code exec |
| **Error path** | Secret included in HTTP response / error page | Secret in `core` dump file or local log rotated weekly |
