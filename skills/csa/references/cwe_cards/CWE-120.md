# CWE-120: Classic Buffer Overflow
> Tier: 2 | Global samples: 89

## 1. Typical Code Patterns

Classic buffer overflow occurs when a fixed-size stack or heap buffer is written with data whose length is not verified against the buffer capacity. The most common manifestations in C/C++ are:

- **Unbounded string copies** — `strcpy(dst, src)` where `dst` is a fixed-size array (`char buf[64]`) and `src` is user-controlled or of unknown length. Same applies to `strcat`, `sprintf`, `vsprintf`, `gets`, `scanf("%s", buf)`.
- **Off-by-one/miscalculated bounds** — `for (i = 0; i <= n; i++) buf[i] = ...` writing one element past the end, or manual pointer arithmetic (`*(dst + len) = c`) without checking `len < capacity`.
- **Incorrect sizeof usage** — `memcpy(buf, src, sizeof(src))` when `src` is a pointer, not an array; or passing the wrong buffer size to `n`-variant functions like `strncpy(buf, src, sizeof(buf))` vs. `strncpy(buf, src, strlen(src))`.
- **Array indexing via attacker-controlled indices** — `buf[user_index] = value` without range checks, especially in loop contexts reading/writing sequential elements.

Tainted data flowing into any of the above functions or patterns is the primary vector. The key discriminator from other buffer-related CWEs (122, 124, 787) is the *absence* of any length check before the write operation.

## 2. CSA Checker Architecture Recommendations

- **Base class:** `BufferOverflowChecker` extending `Checker<check::PreCall, check::PostCall, check::Bind, check::EndFunction>`. Track both symbolic and concrete buffer extents alongside the access offset.  
- **Callbacks:** `check::PreCall` to intercept dangerous runtime library calls (`memcpy`, `strcpy`, `sprintf`, etc.) and infer buffer sizes from the callee parameter list. `check::Bind` to catch direct array writes (`arr[i] = x`) when `i` is unbounded relative to the allocation size.  
- **Tracking granularity:** A `RegionState` map on the ProgramState linking each `MemRegion` to a `BufferDescription` (capacity, current extent, taint flag). Compute symbolic upper/lower bounds for the access index and compare against the symbolic capacity.  
- **Cross-reference:** See `csa_checker_patterns.md` §2.3 (RangeConstraint reasoning), §3.1 (Taint propagation), and §5.2 (CStringChecker integration). A dedicated `GenericBufferOverflowChecker` may subsume or complement `CStringChecker` by handling non-string buffers as well.

## 3. Known High-Frequency False Positive Patterns

- **Fixed-size buffers that are provably never overrun** — The checker may lack path-sensitive range tracking for loops (e.g., `for (i = 0; i < n && i < 64; i++) buf[i] = src[i]`). The inner `i < 64` check is missed when the loop condition is evaluated as a conjunction of symbolic constraints.
- **Buffers managed by external allocators / pools** — Memory regions whose size is known only at runtime via an allocator API that the checker does not model. The checker assumes worst-case (zero capacity), triggering false alarms on every access.
- **Functions receiving a "remaining length" parameter** — Patterns like `write_chunk(buf + offset, &len_remaining, data)` where offset is manually maintained. The checker may lose the relationship between `len_remaining` and the buffer's original capacity.
- **Struct fields with flexible array members (FAM)** — The trailing `char data[]` or `T items[]` member in a `struct` whose true allocation size is `sizeof(struct) + extra`. Without explicit modeling of the overallocation, writes to `p->data[i]` appear out-of-bounds.

## 4. Generic Discriminant Features

- **Textbook:** Straight unbounded copy (`strcpy(dst, src)`) with stack arrays, or a direct literal-index write that exceeds the declared size (`buf[100] = 0` where `buf` is `char[64]`).  
- **Variant / borderline:** Off-by-one in a boundary comparison (`<=` vs `<`), invalid `sizeof` in a `memcpy` length argument, or an integer truncation before the size check (`uint16_t` size cast to `int8_t`). These require deeper range analysis to classify.  
- **Non-bug lookalikes:** Deliberately unsafe code (kernel `copy_to_user` with pre-validated length), Duff's device / loop unrolling that accesses slightly out-of-bounds temporarily, or union-based type-punning between buffers of different sizes.
