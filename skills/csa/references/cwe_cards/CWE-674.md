# CWE-674: Uncontrolled Recursion
> Tier: 2 | Global samples: 29

## 1. Typical Code Patterns

Uncontrolled recursion occurs when a function calls itself (directly or indirectly) without guaranteed termination conditions. The most common manifestations in C/C++ codebases:

- **Missing or insufficient base case:** A recursive function lacks a stopping condition, or the condition is reachable only under narrow inputs (e.g., `if (x > 0) recurse(x)` but `x` is never guaranteed to reach `<= 0`).
- **Mutation of termination variable is absent or non-monotonic:** The argument driving the base-case test is never modified between calls, or is modified in a direction that does not approach the base case (e.g., incrementing toward a less-than test).
- **Indirect recursion cycles:** Two or more functions call each other cyclically (A→B→A) with no depth control. Especially common in mutually recursive parsers, state machines, or plugin dispatch loops.
- **Recursion inside unchecked loops:** A recursive call is made inside a loop whose iteration count is unbounded, effectively multiplying the recursion depth by an uncontrolled factor.
- **Platform-dependent stack assumptions:** Code compiles and runs on a desktop (large default stack) but crashes on embedded or kernel builds (small stack) — the recursion works *today* but is fragile.

## 2. CSA Checker Architecture Recommendations

- **Base class:** `Checker<check::PostCall, check::EndFunction, check::BeginFunction>`.
- **Callbacks:**
  - `check::BeginFunction` — record entry to a function on the exploded graph's call stack.
  - `check::PostCall` — detect self-calls (direct or indirect) by comparing callee `Decl` against a worklist of "recursive" functions identified during traversal.
  - `check::EndFunction` — pop call-stack tracking state.
- **Tracking granularity:** Maintain a per-path `CallStack` (list of `FunctionDecl*`) in the program state. When `A` calls `B` and `B` (or any callee in the same strongly connected component) calls `A` again, flag the second `A` entry if recursion depth exceeds a configurable threshold (default: 1000 frames on desktop, 128 on kernel/embedded targets).
- **Cross-reference:** See `csa_checker_patterns.md §CallStackTracking` and §SCC-based cycle detection.
- **Configuration knobs:** `MaxRecursionDepth`, `DetectIndirect=true`, `SCCThreshold` (cycle-length limit).

## 3. Known High-Frequency False Positive Patterns

- **Divide-and-conquer algorithms:** Quicksort, mergesort, binary tree traversal — by design they recurse, but depth is bounded by input size (logarithmic for balanced trees/quicksort). Whitelist by: (a) the recursion is on a smaller or partitioned input, (b) the SCC is a well-known algorithmic pattern.
- **Tail-recursive loops:** Compilers optimize these to iteration. If the CSA fires before optimization, suppress on `noreturn`-in-disguise patterns (recursive call is the last statement and result is returned directly).
- **Recursive descent parsers:** Legitimate recursive descent has depth bounded by nesting level of the input language. Suppress when recursion follows a formal grammar (recognizable by `consumeToken()` + switch-on-token-type pattern).
- **Signal-safe recursion with explicit depth guards:** Functions that decrement a `static int depth_left` counter and return early if `depth_left <= 0`. Detect: a guard condition checking a monotonically decreasing local/static variable before recursion.
- **Doxygen/metaprogramming trampolines:** A short helper that calls itself with a transformed argument (e.g., typelist iteration) — depth is bounded by compile-time type recursion, not runtime input.

## 4. Generic Discriminant Features

- **Textbook (definite bug):** Recursive call unconditionally reaches itself with no state change — infinite loop. The base-case condition, if it exists, cannot be satisfied because the argument never moves toward it (e.g., `f(i) { if (i<0) return; f(i); }` — `i` unchanged).
- **Variant (probable bug):** The argument moves toward the base case but the movement is too slow relative to input magnitude (e.g., `f(n) { if (n==0) return; f(n-2); }` — odd `n` never reaches `0`). Or the base case exists but depends on a global/volatile that the analysis cannot prove is ever set.
- **Benign (FP candidate):** The recursive function is structurally guaranteed to terminate (e.g., follows a well-founded ordering like structural tree descent on `left/right` children with `null` leaf check). The CSA should not warn when the recursion argument is derived from a pointer that must reach `null` by well-known data structure invariants.
